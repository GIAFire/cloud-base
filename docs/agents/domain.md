# 领域文档

本文件说明工程技能在探索代码库时应如何读取本仓库的领域文档。

## 探索前读取

- 先读取根目录的 `CONTEXT-MAP.md`
- 根据索引读取与任务相关上下文的 `CONTEXT.md`
- 阅读 `docs/adr/` 中与任务相关的系统级决策
- 阅读相关上下文 `docs/adr/` 中的局部决策

若这些文件尚不存在，静默继续，不要仅因缺失而建议预先创建。领域术语或架构决策实际形成时，再通过领域建模流程按需创建。

## 文件结构

本仓库采用多上下文布局：

```text
/
├── CONTEXT-MAP.md
├── docs/adr/                 # 跨上下文、系统级决策
├── gateway/
│   ├── CONTEXT.md
│   └── docs/adr/
├── framework/
│   ├── CONTEXT.md
│   └── docs/adr/
├── modules/
│   └── <业务上下文>/
│       ├── CONTEXT.md
│       └── docs/adr/
└── ui/
    └── <前端上下文>/
        ├── CONTEXT.md
        └── docs/adr/
```

`CONTEXT-MAP.md` 是领域文档入口，仅需读取与当前任务相关的上下文。

## 使用词汇表中的术语

当输出涉及领域概念时，应使用相应 `CONTEXT.md` 中定义的术语，避免改用词汇表明确排除的同义词。

如果所需概念尚未出现在词汇表中，应先判断它是偏离项目语言，还是确实存在领域模型缺口。

## 标明 ADR 冲突

若建议与已有 ADR 冲突，必须明确指出所冲突的 ADR 及重新讨论它的理由，不得静默覆盖既有决策。
